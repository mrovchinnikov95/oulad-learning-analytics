# Где ИИ ошибся и что исправлено

Проект сделан с Claude Code. Здесь собраны ошибки агента из журнала этой работы: что было не так, кто или что это заметил и что изменили. Правила, которые закрывают эти ошибки, записаны в [CLAUDE.md](../CLAUDE.md).

Кто замечал:
- **гейт** — проверки сборки (`sql/25_raw_checks.sql`, `sql/90_checks.sql`) на реальном прогоне;
- **самопроверка** — агент перечитал свой код или разрезал результат до того, как писать вывод;
- **скриншот** — снимок отрисованного дашборда и `scripts/screenshot.mjs`, который падает на предупреждениях консоли;
- **ошибка инструмента** — psql, shell, таймаут;
- **рецензент** — независимые агенты, которые до публикации пытались сломать числа, выводы и воспроизводимость, у каждого свой контекст.

Главный вывод: SQL почти не ошибался в арифметике. Ошибки сидели в допущениях о данных («вес — целое», «ноль — значит ноль», «срок у всех заданий значит одно и то же») и в проверках, которые могли пройти впустую. Ловили их разрез результата до вывода и проверки, которые сначала заставляли упасть.

## Данные и метрики

| Что ИИ сделал не так | Кто заметил | Что исправлено |
|---|---|---|
| Проверял вес задания как целое число. В наборе 14 дробных весов (12.5, 17.5, 7.5) | Гейт сырья на первом прогоне | Вес проверяется как десятичное число. Правило: формат поля проверять по всему файлу, а не по первым строкам |
| Посчитал долю «в срок» по TMA и CMA вместе. Разрез по модулям показал, что у CMA в BBB, CCC и DDD в срок почти никто не сдаёт, а в FFF и GGG — 94%: срок CMA в этих модулях означает что-то другое | Самопроверка: разрез по модулям перед выводами | Правило `rules.on_time_measurable`: «в срок» только по TMA, CMA — в качестве данных (`cma_deadline`) |
| По округлённому выводу 0,0% написал правило «ни одной сдачи CMA в срок». Счётчик дал 9 606 сдач вместо ожидаемых 30 526: в BBB и DDD нашлось по одной сдаче в срок | Самопроверка: сверка счётчика с ожидаемой суммой | Порог «меньше 1%», в тексте «2 из 30 526» |
| Разницу февраль — октябрь прикинул по округлённой таблице: 56,4 − 48,8 = 7,6 п.п. По неокруглённым долям — 7,5 | Сверка с вьюхой фактов | Числа выводов берутся только из `mart.readme_facts` |
| Писал в выводах «студентов», хотя считаются регистрации на поток: один человек бывает в нескольких потоках | Самопроверка текста | Определение в README и правило в CLAUDE.md |

## Проверки

| Что ИИ сделал не так | Кто заметил | Что исправлено |
|---|---|---|
| Сверку итогов приступивших упаковал в одно число: четыре счётчика с множителями 10⁶, 10⁴ и 10². При 12 361 сдавших разряды перекрываются, и разные наборы чисел дают одно значение | Самопроверка до запуска | Четыре отдельные сверки |
| Сверка «должны сдать» по заданиям прошла бы на пустом соединении: 0 расхождений из 0 строк | Самопроверка | Число соединённых заданий входит в результат проверки |
| Порчу CSV в тесте писал через sed с якорем конца строки. Файлы OULAD — с CRLF, шаблон бы не сработал, и тест «прошёл» бы, ничего не испортив | Самопроверка (`od -c`) до запуска | Шаблоны без якоря конца строки |
| Случай «потерянный факт» в тесте порчи писал как вьюху, которая читает саму себя: это ошибка создания, а не проверка | Самопроверка | Старая вьюха переименовывается, новая читает её |

## Окружение и дашборд

| Что ИИ сделал не так | Кто заметил | Что исправлено |
|---|---|---|
| Передавал каталог данных в `\copy` через переменную psql. `\copy` переменные в своей строке не подставляет | Ошибка psql | `\cd :data_dir`, пути к файлам относительные |
| Сверку контрольных сумм выбирал по коду возврата `sha256sum --version`. На macOS системный `sha256sum` отвечает 0, но не знает `--quiet` | Первый запуск сборки | GNU-версия определяется по тексту версии, иначе `shasum` |
| В разведке данных написал коррелированные подзапросы по таблицам без индексов; запрос шёл больше 10 минут | Таймаут | Витрины строятся соединениями по таблицам с ключами |
| Ширина графиков `"container"` при высоте по шагу строки давала предупреждения Vega-Lite | `scripts/screenshot.mjs` | Ширина берётся у карточки при отрисовке |
| Отключил легенду формы у точек «февраль/октябрь», Vega-Lite предупредил о конфликте легенд | `scripts/screenshot.mjs` | Цвет и форма в одной легенде |
| Общий график активности смешивал потоки разной длины в последних неделях | Скриншот | Для «всех потоков» — только недели, которые есть у всех 22 потоков |
| Шкала «февраль/октябрь» начиналась с нуля, точки сжались у правого края: слой линий включал ноль в общую шкалу | Скриншот | Домен шкалы задан в обоих слоях |

## Что из этого следует для работы с ИИ

- Перед выводом разрезать метрику по главным измерениям: среднее прячет поломку в части данных.
- Не верить округлённому выводу, когда текст говорит «ни одного» или «все».
- Каждую проверку сначала заставить упасть на заведомо плохих данных (`scripts/test_controls.sh`) и проверить, что она не проходит на пустом множестве.
- Итоговые числа подтверждать вторым расчётом, который писался без доступа к первому.
- График принимать по картинке, а не по коду спеки.
